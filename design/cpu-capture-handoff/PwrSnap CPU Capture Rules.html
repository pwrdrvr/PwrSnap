Combinations Every card is live. High CPU picks one of Spike or Sustained; Slow burn turns on independently. At least one rule is always on. Each rule keeps its own threshold and duration, so switching Spike and Sustained restores that rule's values.

Sustained onlyshipped default

Today's default trigger, unchanged: two consecutive 2 s samples at 50%. Its checkbox is the last one on, so it is locked.

Spike onlylegacy spike

One 2 s sample at 50%. Choose 1 s to sample every second while this rule is on.

Spike at 1 s1 s cadence

The sampler runs every second, so Slow burn's sample counts double for the same duration. The labels update to say so.

Sustained + Slow burnboth on

Catches hot bursts and steady background churn in one armed session. Either checkbox can be turned off.

Spike + Slow burnboth on

If one sample is both a spike and the end of a slow burn, one capture is saved and it names both rules.

Slow burn onlylegacy slowburn

High CPU is off but keeps its mode and values. Slow burn is the last rule on, so it is locked.

Last rule turned offguard

Clicking or pressing Space on the last checked rule leaves it checked and says why. The checkbox stays focusable (aria-disabled, not disabled) so the reason can be found.

Invalid thresholdvalidation

Nothing is saved until the value is a whole number from 1 to 400. Escape restores the saved value; Enter or leaving the field saves a valid one.

Slow burn above High CPUsoft warning

Allowed but flagged: a slow burn at or above the High CPU threshold never fires first.

Behavior and wording The same rules, labels and messages ship in PwrGit, PwrSnap and PwrAgent. Only the surrounding pane follows each app.

Slow burn15% · 4 s4, 10, 30, 60 sSame test as Sustained, with a lower threshold. Independent of High CPU.

CPU is each process's CPU time over a sample, divided by the sample's wall time, so 100% is one core fully busy and multi-threaded work can read higher. The sampler runs every 2 s, or every 1 s while an enabled Spike rule is set to 1 s. Duration counts consecutive samples, so detection lands at the end of a sample, never instantly, and a short burst inside a sample is averaged with the rest of it.

When rules match together

One capture per process. If several rules match on the same sample, or another rule matches while that process is already being captured, no second capture starts. The capture records every rule that matched, in the order Spike, Sustained, Slow burn.
